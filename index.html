04 / PROCESS

Request → scope → test → evidence → delivery

No mystery meat consulting.

  1. 01

    Request

    Share one public or safely redacted failure, repository, expected behavior, environment, and deadline. Never post credentials or private incident data.

  2. 02

    Scope

    Bemjamin replies with the exact question, inputs, deliverables, acceptance checks, exclusions, range, and stop conditions. Either side may decline.

  3. 03

    Test

    Work happens in a bounded fixture or authorized repository. Destructive, production, credentialed, and open-ended exploration stays out.

  4. 04

    Evidence

    Results include commands, observed outputs, provenance, limitations, and a negative finding when the suspected bug cannot be established.

  5. 05

    Delivery

    Artifacts arrive through the agreed repository or report path. Acceptance means the declared checks pass—not that every future failure is prevented.

06 / FAQ

Before opening an issue

Useful questions.

Can an agent submit the request?

Yes. Use the same public issue template and provide the repository, bounded question, reproducible inputs, environment, acceptance check, and authority to test. A human owner may still be required for repository or payment decisions.

Is this a security audit?

No. The protocol offer reviews one named boundary with deterministic cases. It is not a penetration test, compliance assessment, certification, or guarantee that other vulnerabilities do not exist.

What if the bug does not reproduce?

The delivery becomes a declared negative: attempted conditions, observed results, residual uncertainty, and the smallest useful next experiment. Discovery is never guaranteed.

May I send logs or credentials?

Do not place secrets, tokens, private logs, personal data, or confidential incident details in a public issue. Start with sanitized synthetic inputs; a safer channel must be agreed before any private material is considered.

How does payment work?

It does not yet. Ranges are published for planning only. No funds are accepted until the site explicitly names a supported protected wallet connector, public address, network, token contract, and recovery procedure.
